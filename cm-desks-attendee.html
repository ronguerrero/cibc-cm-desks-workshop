Capital Markets · hands-on lab

Build the Trading Floor Copilot

Three desks build in parallel — each group follows only its own track to build a governed data product and a desk agent. Then the Admin track pieces them together into one firm-wide copilot, applies the cross-desk governance, and runs the reveal. Every step shows both surfaces — a Genie Code prompt (Path A) and the equivalent code/notebook (Path B) — so each group builds the way it prefers.

Setup Desk A · Portfolio Desk B · Research Desk C · Market Admin · Integration

How to run this. Assign one group per desk (A/B/C). Each group does only its track, end-to-end, and records its hand-off IDs at the end. When all three are done, the Admin (facilitator, or a fourth group) runs the Admin track using those IDs. Placeholders: <catalog> is your catalog; all desks share the seed's catalog + schema_prefix, and desk product schemas (cm_portfolio_gold, etc.) are fixed names.

Before you start (facilitator). The workspace needs: Unity Catalog + a serverless SQL warehouse; Foundation Model APIs (databricks-claude-haiku-4-5) with AI features on; Agent Bricks (Knowledge Assistant + Multi-Agent Supervisor); Genie + Genie One (chat/routing is Public Preview — enroll); Discover domains (Public Preview); and account groups cm_privileged / cm_all_access for the rating mask. Full list in FACILITATOR.md.

Driving Genie Code. Start a fresh Genie Code chat for each step — it keeps context small. Let it plan and run end-to-end; don't tell it to "confirm" or "approve." Its tools follow the open surface, so be on the right page first: the Genie surface for spaces, the Agent Bricks skill for the KA / desk agents / Copilot (Genie Code upgrades the SDK itself — this can take several retries and may fall back to the CLI; let it run, don't nudge it), and keep Discover open for the domain step (D2). Prefer the code/notebook path? Each step has a matching Path-B script in the repo.

D1

Cross-desk governance — mask + chinese-wall

One shared wall across every desk's data — it follows the data through Genie, functions, and the agents.
Genie Code
Create a cm_governance schema. Add a column mask on clients.credit_rating returning *** unless the caller is in cm_privileged. Add a chinese-wall: a coverage_acl table mapping user → coverage officer, and row-filter functions so a user sees only clients whose coverage officer maps to them. Apply the filter to all three desks' assets: cm_portfolio_gold.clients and positions, cm_research_gold.research_docs, and cm_market_gold.signal_matches.
Path B — code
governance/01_abac_and_rls.py   # widgets: catalog, schema_prefix
# mask_rating (needs account group cm_privileged) + coverage_acl chinese-wall;
# SET MASK / SET ROW FILTER applied across all three desks' assets
Checkpoint A user scoped to one coverage officer (e.g. "Sofia" → AC, MG) sees only those clients across all three desks; credit_rating shows *** for non-privileged callers.

Account-admin prerequisite for the mask: credit_rating masking keys off is_account_group_member('cm_privileged'), which only recognizes account groups. Have an account admin create account groups cm_privileged and cm_all_access and add the desk-head demo user to cm_privileged before the reveal — otherwise the rating masks to *** for everyone. The chinese-wall row filter needs no groups (it uses coverage_acl + current_user()).
